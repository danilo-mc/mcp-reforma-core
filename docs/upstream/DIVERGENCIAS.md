# Divergências entre a SPEC e o contrato real dos upstreams (M0, 2026-11-21)

Registro das diferenças encontradas na descoberta (PLANO §4.2). Cada item deve gerar ajuste
rastreável em `SPEC.md` (não editado nesta etapa).

| # | SPEC diz | Realidade nos SHAs fixados | Impacto / sugestão |
|---|---|---|---|
| D1 | Motores Java (implícito Java 21; ADR005 do upstream fala em Java 21) | **Java 25** + Spring Boot 4.1.2 (ADR011 regular / ADR013 Simples). Imagens `eclipse-temurin:25-jdk/jre` | Nenhum no servidor; registrar na SPEC |
| D2 | Estrutura `engines/regular.Dockerfile` etc. (SPEC §11) | PLANO §5.1 pede `engines/regular/Dockerfile`; implementado assim (um diretório por motor, contexto de build isolado) | Atualizar SPEC §11 |
| D3 | Rota `POST /observabilidade/regime-geral` | Caminho completo: `POST /api/calculadora/observabilidade/regime-geral` (context path `/api`) | `ENGINE_REGULAR_URL=http://engine-regular:8080/api` + `/calculadora/observabilidade/regime-geral` |
| D4 | Rota Simples `POST /api/calculadora/observabilidade/simples-nacional` | Existe, mas marcada **OBSOLETO**; a recomendada é `.../simples-nacional/nao-assistido` (linha de alíquotas do contribuinte `aliquotasEfetivas` por anexo, NFS-e suportada) | Decidir qual rota a ferramenta `calcular_simples` usa; sugerido: não assistida, mantendo a clássica como compatibilidade |
| D5 | Status por item: `CALCULADO`, `CALCULO_SIMULADO`, `INCONSISTENCIA_ENTRADA`, `NAO_IMPLEMENTADO`, `FALHA_TECNICA` | Regular: exatamente esses (`objetos[].estadoItem`). **Simples: não tem `CALCULO_SIMULADO` e tem `NAO_CALCULADO`** (+ `motivoEstado`) | Ampliar enum/`explicar_status` com `NAO_CALCULADO` e códigos de `motivoEstado` |
| D6 | Entrada `data_fato_gerador` (data) | Regular: `dhFatoGerador` **date-time com offset** (`2027-03-15T10:00:00-03:00`); Simples: `data` `AAAA-MM-DD` | Servidor converte data → `T00:00:00-03:00` (ou hora informada) para o regular |
| D7 | `municipio_ibge` "traduzir se diferente" | Regular usa **código IBGE de 7 dígitos como inteiro** (`municipio: 3550308`), mais `uf` obrigatória e consistente (senão 422 `REG-018`). Simples não recebe município | Só converter string → número; validar UF×município via `/dados-abertos/ufs/municipios` |
| D8 | Item com `valor`, `quantidade`, `ncm`/`nbs`, `cst`, `cclasstrib` | Regular: `numero`, `ncm` ou `nbs` (exclusivos), `cst`, `cClassTrib`, `baseCalculo` (não "valor"), `quantidade`, `unidade`, grupos `impostoSeletivo`, `tributacaoRegular`, `gComponentesBC` | Mapear `valor` → `baseCalculo` (ou `gComponentesBC.vProd`) |
| D9 | Injetar alíquotas de `rates/` ≥ 2027; usar internas em 2026 | Confirmado: `itens[].aliquotasNominais {cbs, ibsEstadual, ibsMunicipal, impostoSeletivo{adValorem, adRem}}` em **pontos percentuais**, **por item**; obrigatório ≥ 2027 (`REG-037`) e **proibido** < 2027 (`REG-036`). Resultado sai `CALCULO_SIMULADO` + header `x-warning-dados-simulados: 6` | `rates/` deve guardar % (ou converter 0.113 → 11.3); replicar por item; repassar o header ao recibo |
| D10 | `calcular_simples` com `pIBSSN/pCBSSN` "quando o motor exigir" | Sempre exigidas (clássica: por item; não assistida: `aliquotasEfetivas` por anexo, salvo `SOMENTE_RECEITA`). O motor do Simples **não tem alíquotas próprias** | O usuário (ou `rates/`) precisa fornecer as alíquotas efetivas do Simples |
| D11 | Simples só ≥ 2027 | Confirmado: em 2026 nenhum `tpDoc` está habilitado → 422 `VSN-015` | Manter validação prévia no servidor |
| D12 | Valores numéricos | Respostas trazem decimais como **strings** (`"247.30"`); Simples também na entrada (`"950.00"`) | Não converter para float ao exibir; manter string para não reprocessar arredondamento |
| D13 | Recibo: `output_sha256` = SHA-256 do JSON canônico da resposta bruta | (a) `erros[].type` contém o Host da requisição (sem porta); no Simples ainda sem `/api`; (b) **ordem de `erros[]` VAL-0xx não determinística** no regular; (c) respostas 422 têm `timestamp` | Canonicalizar antes do hash: ordenar `erros`/`errors`, remover `timestamp`, e/ou chamar sempre com o mesmo Host. Sem isso `reproduzir_calculo` falha em entradas inválidas |
| D14 | `versao` retorna "versão da base de dados do motor" | Regular: `GET /api/calculadora/dados-abertos/versao`; Simples: `GET /api/versao`; ambos e todas as respostas com headers `X-CALC-APP-VERSION`/`X-CALC-DB-VERSION`. **DANFSe não tem endpoint de versão** | DANFSe: usar SHA/tag fixados (env `UPSTREAM_DANFSE_SHA`) |
| D15 | `buscar_classificacao` usa "rotas de dados abertos de cClassTrib/NBS/NCM" do motor | Só o **regime regular** expõe essas rotas; o Simples expõe apenas atividades (`/calculadora/simples-nacional/atividades`) | `buscar_classificacao` sempre consulta o engine-regular |
| D16 | DANFSe `stc` (0/1/2) e `canhoto` | Confirmados (query `stc`, `canhoto`); erros de entrada e internos ambos HTTP 400 JSON `{"sucesso":false,"mensagem"}`; 413 acima de `XML_MAX_SIZE_BYTES` | Tratar 400 como "XML/parâmetro inválido" com mensagem do motor |
| D17 | Issues #3/#10 (arredondamento) a anotar em `known_issues` | Ambas OPEN, mas **não reproduzem** no SHA `f1eebd7` com os payloads das próprias issues | Manter em `known_issues` enquanto abertas, com nota "não reproduzido em f1eebd7" |
| D18 | Issues DANFSe NT 008 #4, #9, #12 | Todas OPEN; além delas #3, #5, #7, #10, #11 (NT 009 em produção em 01/12/2026) afetam conteúdo fiscal | Ampliar lista de `known_issues` do DANFSe |
| D19 | Imagens "oficiais" | Não há imagem publicada pelo upstream; construímos a partir do código oficial sem patches. Testes upstream não rodam no build (`-DskipTests`) | Documentado nos Dockerfiles |

## Ajustes de desenho posteriores ao M0

| # | SPEC diz | Decisão | Motivo |
|---|---|---|---|
| D21 | §5.7 e §13.3: PDF do DANFSe entregue como **URL SAS de delegação de usuário** (24 h, só leitura) | Em modo `blob` a ferramenta devolve `<PDF_PUBLIC_BASE_URL>/pdf/<id>` (URL pública do Front Door; id aleatório de 144 bits, validado por `^[A-Za-z0-9_-]{24}$`) e o servidor faz *streaming* do blob em `GET /pdf/:id`, lendo com a identidade gerenciada (`DefaultAzureCredential`). `Content-Type: application/pdf`, `Cache-Control: no-store`; 404 se o blob não existe ou tem mais de 24 h (data de criação do blob). Papel `Storage Blob Delegator` removido; o lifecycle de 1 dia continua apagando os blobs. Modo `local` inalterado | O Storage tem `publicNetworkAccess: Disabled` e só private endpoint: uma URL SAS para `*.blob.core.windows.net` não abre para o usuário final. Servir pelo Front Door mantém o Storage fechado, reaproveita WAF/TLS do domínio público e não expõe nome de conta nem assinatura na URL |
